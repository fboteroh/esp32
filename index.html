ESP32: de la placa al primer programa

Una guía para tocar y explorar. Empieza por el hardware (qué trae la placa y cómo conectarla) y sigue con el software (cómo programarla con Arduino IDE). Todo lo resaltado en el pinout y en el simulador es clicable.

1. ¿Qué es el ESP32?

Es un microcontrolador de Espressif con WiFi y Bluetooth integrados. Se vende montado en una placa de desarrollo (DevKit) que añade USB, regulador de voltaje y botones. Aquí usamos como modelo la DevKit de 30 pines.

2 núcleosXtensa LX6 hasta 240 MHz
520 KBde RAM (SRAM); 4 MB de memoria flash en la mayoría de módulos
WiFi + BTWiFi 2.4 GHz (802.11 b/g/n), Bluetooth clásico y BLE
3,3 VTodo el chip trabaja a 3,3 V, no a 5 V
~25 GPIOutilizables en la DevKit, con ADC, DAC, PWM, touch, I2C, SPI y UART

3. Recursos de la placa

Abre cada recurso para ver qué es, cómo se usa y un ejemplo mínimo.

GPIO digitales (entrada y salida)

Cada pin puede ser salida (3,3 V o 0 V) o entrada. Como entrada con un botón, usa la resistencia interna INPUT_PULLUP: el pin lee 1 en reposo y 0 al pulsar.

pinMode(2, OUTPUT);  digitalWrite(2, HIGH);
pinMode(4, INPUT_PULLUP);  int b = digitalRead(4);
ADC: leer voltajes analógicos

Convierte un voltaje de 0 a 3,3 V en un número de 0 a 4095 (12 bits). Úsalo con potenciómetros, LDR y sensores analógicos. Prefiere los pines ADC1 (32 a 39): el ADC2 no funciona mientras el WiFi está activo. La lectura no es muy lineal en los extremos.

int v = analogRead(34);          // 0..4095
float volt = v * 3.3 / 4095.0;
DAC: generar voltajes analógicos

Solo GPIO25 y GPIO26 tienen DAC de 8 bits (0 a 255, equivale a 0 a 3,3 V). Sirve para tonos simples o referencias de voltaje.

dacWrite(25, 128);  // aprox. 1,65 V
PWM (LEDC): brillo y motores

Casi cualquier pin de salida puede generar PWM, con hasta 16 canales. Alterna encendido y apagado muy rápido; el porcentaje de tiempo encendido controla el brillo de un LED o la velocidad de un motor.

ledcAttach(4, 5000, 8);   // pin, frecuencia, bits (core 3.x)
ledcWrite(4, 128);        // 50% de brillo
Sensores táctiles (touch)

Diez pines (T0 a T9) detectan el roce de un dedo sin botón físico. El valor baja cuando tocas el pin.

int t = touchRead(T0);   // GPIO4
UART, I2C y SPI (comunicación)

UART: dos hilos TX/RX, para GPS, módulos y el monitor serie (UART0 va al USB). I2C: dos hilos SDA y SCL para muchos sensores y pantallas OLED con direcciones distintas (por defecto GPIO21 y GPIO22). SPI: cuatro hilos (MOSI, MISO, SCK, SS), más rápido, para tarjetas SD y pantallas TFT (VSPI: 23, 19, 18, 5).

Wire.begin(21, 22);  // I2C
Serial2.begin(9600, SERIAL_8N1, 16, 17);  // UART2
SPI.begin(18, 19, 23, 5);  // SCK, MISO, MOSI, SS

Práctica útil: si un módulo I2C no responde, este escáner lista las direcciones que encuentra en el bus.

#include <Wire.h>

void setup() {
  Serial.begin(115200);
  Wire.begin(21, 22);     // SDA, SCL
}

void loop() {
  Serial.println("Buscando dispositivos I2C...");
  int n = 0;
  for (byte dir = 1; dir < 127; dir++) {
    Wire.beginTransmission(dir);
    if (Wire.endTransmission() == 0) {
      Serial.printf("Dispositivo en 0x%02X\n", dir);
      n++;
    }
  }
  if (n == 0) Serial.println("Ninguno: revisa SDA, SCL, GND y alimentación");
  delay(5000);
}
WiFi y Bluetooth

Se usan por software, sin hardware externo. Con WiFi puedes conectarte a tu red, crear un servidor web o enviar datos a internet. Con BLE puedes comunicarte con el celular. La antena está en el módulo: no pongas metal ni la tapes.

#include <WiFi.h>
WiFi.begin("MiRed", "clave");
Ahorro de energía (deep sleep)

El chip puede dormir y despertar por un temporizador, un pin o un toque. Dormido consume microamperios en el chip (la placa, por su regulador y el conversor USB, consume bastante más). Útil para proyectos con batería.

esp_sleep_enable_timer_wakeup(10 * 1000000ULL); // 10 s
esp_deep_sleep_start();
Botones y LED de la placa

EN: reinicia el programa. BOOT (GPIO0): se mantiene pulsado para entrar en modo de carga si la placa no se programa sola. En muchas placas hay un LED en GPIO2 para pruebas, pero no todas lo traen.

4. Cómo conectarla

Alimentación

Por USB (5 V) lo más simple. Si usas el pin VIN, entrega 5 V (el regulador baja a 3,3 V). El pin 3V3 sale a 3,3 V para sensores pequeños. Comparte siempre GND entre la placa y tus componentes.

Los pines no soportan 5 V

Una señal de 5 V en un GPIO puede dañar el chip. Con sensores de 5 V usa un convertidor de nivel o un divisor de voltaje.

Corriente por pin

Un pin entrega poca corriente (aprox. 12 mA es una cifra prudente; el máximo absoluto ronda los 40 mA). Un LED necesita resistencia de 220 a 330 Ω. Motores, relés y tiras LED se conectan con transistor o driver y fuente propia.

Pines que debes evitar

GPIO6 a 11 están ocupados por la memoria flash: no los uses. Los pines 0, 2, 5, 12 y 15 son de arranque (strapping): si los fuerzas a un nivel incorrecto al encender, la placa no arranca.

Conexiones típicas

WiFi en profundidad

El ESP32 puede conectarse a una red, crear la suya o ambas cosas. Tres ideas básicas: la red se identifica con un SSID, cada dispositivo recibe una dirección IP (por DHCP) y los servicios se ofrecen por puertos (la web usa el 80).

ModoQué haceCuándo usarlo
WIFI_STASe conecta a un router o al hotspot del celularEnviar datos a internet o ser accesible desde la red local
WIFI_APCrea su propia red (IP por defecto 192.168.4.1)Prácticas sin router; el celular se conecta directo a la placa
WIFI_AP_STAAmbos a la vezCasos avanzados
Ojo con la redSolo trabaja en 2,4 GHz: si usas el hotspot del celular, desactiva la banda de 5 GHz. Las redes que piden usuario y contraseña (WPA2-Enterprise) no funcionan con WiFi.begin(red, clave); en clase usa un hotspot o el modo AP. Mientras el WiFi está activo, el ADC2 no funciona (usa GPIO32 a 39). Nunca publiques tu clave WiFi en un repositorio.

Ejemplo 1: escáner de redes (modo STA)

Lista las redes cercanas con su intensidad de señal (RSSI: más cercano a 0 dBm es mejor señal; -50 es excelente, -80 es débil).

#include <WiFi.h>

void setup() {
  Serial.begin(115200);
  WiFi.mode(WIFI_STA);
  WiFi.disconnect();
  delay(100);
}

void loop() {
  int n = WiFi.scanNetworks();
  Serial.printf("%d redes encontradas\n", n);
  for (int i = 0; i < n; i++) {
    Serial.printf("%2d  %-24s  %4d dBm  canal %d\n",
                  i + 1, WiFi.SSID(i).c_str(), WiFi.RSSI(i), WiFi.channel(i));
  }
  delay(5000);
}

Ejemplo 2: servidor web que controla un LED

Cambia RED y CLAVE. Al conectarse, el monitor serie muestra la IP; escríbela en el navegador de un celular o PC conectado a la misma red.

#include <WiFi.h>
#include <WebServer.h>

const char* RED = "TU_RED";
const char* CLAVE = "TU_CLAVE";
const int LED = 2;
WebServer server(80);
bool ledOn = false;

String pagina() {
  String h = "<meta name='viewport' content='width=device-width,initial-scale=1'>";
  h += "<h1>ESP32 EAFIT</h1><p>LED: <b>";
  h += ledOn ? "ENCENDIDO" : "APAGADO";
  h += "</b></p><a href='/on'><button>Encender</button></a> ";
  h += "<a href='/off'><button>Apagar</button></a>";
  return h;
}

void poner(bool v) {
  ledOn = v;
  digitalWrite(LED, v);
  server.sendHeader("Location", "/");
  server.send(303);
}

void setup() {
  Serial.begin(115200);
  pinMode(LED, OUTPUT);
  WiFi.mode(WIFI_STA);
  WiFi.begin(RED, CLAVE);
  Serial.print("Conectando");
  while (WiFi.status() != WL_CONNECTED) { delay(500); Serial.print("."); }
  Serial.print("\nAbre en el navegador: http://");
  Serial.println(WiFi.localIP());
  server.on("/", []() { server.send(200, "text/html; charset=utf-8", pagina()); });
  server.on("/on", []() { poner(true); });
  server.on("/off", []() { poner(false); });
  server.begin();
}

void loop() {
  server.handleClient();
}

Envía una lectura del potenciómetro (GPIO34) a ThingSpeak (servicio gratuito, requiere cuenta y un canal con “Write API Key”). Su límite gratuito es una escritura cada 15 s.

Bluetooth Low Energy (BLE) en profundidad

BLE está pensado para enviar pocos datos con muy poco consumo (sensores, wearables). El celular es el central (cliente) y el ESP32 el periférico (servidor). Funciona así:

  • Advertising: el ESP32 “grita” su nombre para que lo encuentren.
  • Servicio: un grupo de datos relacionados, identificado con un UUID.
  • Característica: un dato dentro del servicio, con propiedades: READ (se lee), WRITE (el celular escribe) y NOTIFY (el ESP32 avisa cuando cambia).
WiFiBLE
DatosMucho (páginas web, archivos)Poco (lecturas, comandos)
ConsumoAltoBajo
Necesita routerSí (o modo AP)No, conexión directa
Ideal paraInternet, dashboardsControl desde celular, wearables

Ejemplo 5: servidor BLE con notificaciones y LED

Instala en el celular la app gratuita nRF Connect. Escanea, conecta con ESP32-EAFIT, activa las notificaciones de la primera característica (verás un contador) y escribe 1 o 0 como texto en la segunda para encender o apagar el LED. Si el compilador dice que el programa es demasiado grande, elige Herramientas → Partition Scheme → Huge APP.

#include <BLEDevice.h>
#include <BLEServer.h>
#include <BLEUtils.h>
#include <BLE2902.h>

#define SERVICE_UUID "4fafc201-1fb5-459e-8fcc-c5c9c331914b"
#define CHAR_DATO    "beb5483e-36e1-4688-b7f5-ea07361b26a8"
#define CHAR_LED     "d1e3b6a2-5c4f-4a8e-9b1d-2f6c7a8e9f01"

const int LED = 2;
BLECharacteristic *cDato;
bool conectado = false;

class Servidor : public BLEServerCallbacks {
  void onConnect(BLEServer *s) { conectado = true; }
  void onDisconnect(BLEServer *s) {
    conectado = false;
    BLEDevice::startAdvertising();   // permite reconectar
  }
};

class EscrituraLed : public BLECharacteristicCallbacks {
  void onWrite(BLECharacteristic *c) {
    auto v = c->getValue();
    digitalWrite(LED, (v.length() && v[0] == '1') ? HIGH : LOW);
  }
};

void setup() {
  Serial.begin(115200);
  pinMode(LED, OUTPUT);
  BLEDevice::init("ESP32-EAFIT");
  BLEServer *srv = BLEDevice::createServer();
  srv->setCallbacks(new Servidor());
  BLEService *svc = srv->createService(SERVICE_UUID);

  cDato = svc->createCharacteristic(CHAR_DATO,
          BLECharacteristic::PROPERTY_READ | BLECharacteristic::PROPERTY_NOTIFY);
  cDato->addDescriptor(new BLE2902());

  BLECharacteristic *cLed = svc->createCharacteristic(CHAR_LED,
          BLECharacteristic::PROPERTY_WRITE);
  cLed->setCallbacks(new EscrituraLed());

  svc->start();
  BLEDevice::getAdvertising()->addServiceUUID(SERVICE_UUID);
  BLEDevice::startAdvertising();
  Serial.println("BLE listo: busca ESP32-EAFIT");
}

void loop() {
  static int n = 0;
  if (conectado) {
    String s = String(n++);
    cDato->setValue(s.c_str());
    cDato->notify();
  }
  delay(1000);
}

ESP-NOW: comunicación directa entre placas

Es un protocolo de Espressif que usa la radio WiFi para enviar mensajes de hasta 250 bytes entre ESP32 sin router ni conexión a internet. Cada placa se identifica por su dirección MAC (no por IP). Tiene muy baja latencia y es ideal para control remoto de un robot o una red de sensores en un laboratorio. Puede enviar a un destino (unicast) o a todos (broadcast), y admite hasta 20 pares.

Pasos1) Carga el receptor y copia la MAC que imprime en el monitor serie. 2) Pega esa MAC en el emisor (formato 0xAA, separado por comas). 3) Carga el emisor. Si además te conectas a un router, ESP-NOW usa el canal de ese router: ambas placas deben estar en el mismo canal.

Ejemplo 6: receptor ESP-NOW

#include <WiFi.h>
#include <esp_now.h>

typedef struct {
  int id;
  float valor;
} Mensaje;
Mensaje msg;

// Firma para el paquete ESP32 3.x (en 2.x el primer parámetro es const uint8_t *mac)
void alRecibir(const esp_now_recv_info_t *info, const uint8_t *datos, int len) {
  if (len != sizeof(msg)) return;
  memcpy(&msg, datos, sizeof(msg));
  Serial.printf("id=%d  valor=%.2f V\n", msg.id, msg.valor);
}

void setup() {
  Serial.begin(115200);
  WiFi.mode(WIFI_STA);
  Serial.print("Mi MAC: ");
  Serial.println(WiFi.macAddress());
  if (esp_now_init() != ESP_OK) {
    Serial.println("Error iniciando ESP-NOW");
    return;
  }
  esp_now_register_recv_cb(alRecibir);
}

void loop() {}

Ejemplo 7: emisor ESP-NOW

Envía la lectura de un potenciómetro (GPIO34) cada segundo.

#include <WiFi.h>
#include <esp_now.h>

// MAC del receptor: reemplázala por la que imprimió tu placa
uint8_t destino[] = {0xAA, 0xBB, 0xCC, 0xDD, 0xEE, 0xFF};

typedef struct {
  int id;
  float valor;
} Mensaje;
Mensaje msg;

void setup() {
  Serial.begin(115200);
  WiFi.mode(WIFI_STA);
  if (esp_now_init() != ESP_OK) {
    Serial.println("Error iniciando ESP-NOW");
    return;
  }
  esp_now_peer_info_t par = {};
  memcpy(par.peer_addr, destino, 6);
  par.channel = 0;          // 0 = canal actual
  par.encrypt = false;
  if (esp_now_add_peer(&par) != ESP_OK) {
    Serial.println("No se pudo agregar el receptor");
  }
}

void loop() {
  msg.id = 1;
  msg.valor = analogRead(34) * 3.3 / 4095.0;
  esp_err_t r = esp_now_send(destino, (uint8_t *)&msg, sizeof(msg));
  Serial.println(r == ESP_OK ? "Enviado" : "Fallo al enviar");
  delay(1000);
}

Reto: el receptor enciende un LED cuando valor pasa de 2,0 V, y envía de vuelta una confirmación (necesitará registrar al emisor como par).

MQTT: publicar y suscribirse

MQTT es el protocolo más usado en IoT. Los dispositivos no hablan entre sí: todos se conectan a un broker (servidor). Quien tiene un dato lo publica en un tópico (por ejemplo eafit/mc4012/ana/adc) y todos los que estén suscritos a ese tópico lo reciben. Funciona sobre WiFi y necesita internet o un broker en tu red.

ESP32 (sensor) --publica--> [ BROKER ] --entrega--> PC / celular / otro ESP32
                              ^                          (suscritos al tópico)
PC / celular   --publica------+   (ej. orden "1" al tópico del LED)
Broker público de pruebasEl ejemplo usa test.mosquitto.org, abierto, sin clave y sin cifrado: cualquiera puede leer tus mensajes. Úsalo solo para aprender, no envíes datos sensibles y cambia TU_NOMBRE por algo único para no mezclarte con otros estudiantes. Para proyectos reales usa un broker propio (por ejemplo Mosquitto en una Raspberry Pi) con usuario y TLS.

Ejemplo 8: cliente MQTT (publica el ADC y recibe órdenes para el LED)

Librería: “PubSubClient” de Nick O’Leary. Para probar, usa una aplicación cliente como MQTT Explorer o MQTTX en el computador: suscríbete a eafit/mc4012/TU_NOMBRE/# y publica 1 o 0 en el tópico .../led.

#include <WiFi.h>
#include <PubSubClient.h>

const char* RED = "TU_RED";
const char* CLAVE = "TU_CLAVE";
const char* BROKER = "test.mosquitto.org";
const int PUERTO = 1883;
const char* T_ADC = "eafit/mc4012/TU_NOMBRE/adc";
const char* T_LED = "eafit/mc4012/TU_NOMBRE/led";
const int LED = 2;

WiFiClient wifi;
PubSubClient mqtt(wifi);

void alMensaje(char* topic, byte* payload, unsigned int len) {
  String s;
  for (unsigned int i = 0; i < len; i++) s += (char)payload[i];
  Serial.printf("[%s] %s\n", topic, s.c_str());
  if (String(topic) == T_LED) digitalWrite(LED, s == "1" ? HIGH : LOW);
}

void conectarMQTT() {
  while (!mqtt.connected()) {
    String id = "esp32-" + String((uint32_t)ESP.getEfuseMac(), HEX);
    Serial.print("Conectando a MQTT... ");
    if (mqtt.connect(id.c_str())) {
      Serial.println("OK");
      mqtt.subscribe(T_LED);
    } else {
      Serial.printf("fallo (rc=%d), reintento en 3 s\n", mqtt.state());
      delay(3000);
    }
  }
}

void setup() {
  Serial.begin(115200);
  pinMode(LED, OUTPUT);
  WiFi.begin(RED, CLAVE);
  while (WiFi.status() != WL_CONNECTED) delay(500);
  Serial.println("WiFi OK");
  mqtt.setServer(BROKER, PUERTO);
  mqtt.setCallback(alMensaje);
}

void loop() {
  if (!mqtt.connected()) conectarMQTT();
  mqtt.loop();                      // atiende los mensajes entrantes

  static unsigned long t = 0;
  if (millis() - t > 2000) {
    t = millis();
    char buf[8];
    snprintf(buf, sizeof(buf), "%d", analogRead(34));
    mqtt.publish(T_ADC, buf);
  }
}

Conceptos para profundizar: QoS (0 = como máximo una vez, 1 = al menos una vez; PubSubClient solo suscribe en 0 o 1), retain (el broker guarda el último valor para quien se suscriba después) y los comodines + y # en las suscripciones.

Prácticas con sensores y actuadores

Cuatro prácticas progresivas. Cada una incluye el diagrama de cableado y el código completo. Monta siempre el circuito con la placa desconectada del USB.

Leyenda de los diagramas: rojo = alimentación, negro = GND, azul = señal. El zigzag es una resistencia.

Práctica 1: pulsador que alterna un LED

Materiales: LED, resistencia de 220 Ω, pulsador, protoboard. Conceptos: salida digital, entrada con INPUT_PULLUP, antirrebote con millis().

const int LED = 4;
const int BTN = 13;
bool estado = false;
bool previo = HIGH;
unsigned long t0 = 0;

void setup() {
  Serial.begin(115200);
  pinMode(LED, OUTPUT);
  pinMode(BTN, INPUT_PULLUP);
}

void loop() {
  bool lectura = digitalRead(BTN);
  if (previo == HIGH && lectura == LOW && millis() - t0 > 50) {
    estado = !estado;
    digitalWrite(LED, estado);
    Serial.println(estado ? "LED encendido" : "LED apagado");
    t0 = millis();
  }
  previo = lectura;
}

Reto: haz que el LED parpadee mientras el botón esté pulsado. Pregunta: ¿por qué el pulsador no necesita resistencia externa?

Práctica 2: potenciómetro y brillo con PWM

Materiales: potenciómetro de 10 kΩ, LED, resistencia de 220 Ω. Conceptos: ADC de 12 bits, map(), PWM.

const int POT = 34;
const int LED = 4;

void setup() {
  Serial.begin(115200);
  ledcAttach(LED, 5000, 8);          // pin, frecuencia (Hz), resolución (bits)
}

void loop() {
  int lectura = analogRead(POT);                 // 0 a 4095
  int duty = map(lectura, 0, 4095, 0, 255);      // 0 a 255
  ledcWrite(LED, duty);
  Serial.printf("ADC=%d  PWM=%d  V=%.2f\n", lectura, duty, lectura * 3.3 / 4095.0);
  delay(100);
}

Observa: abre el Serial Plotter y gira el potenciómetro. Reto: suaviza la lectura promediando 10 muestras.

Práctica 3: temperatura y humedad con DHT22

Materiales: sensor DHT22 (si es el sensor de 4 pines sin placa, agrega una resistencia de 10 kΩ entre DATA y 3V3; los módulos de 3 pines ya la traen). Librerías (Administrar bibliotecas): “DHT sensor library” de Adafruit y, si lo pide, “Adafruit Unified Sensor”.

#include <DHT.h>

#define PIN_DHT 4
DHT dht(PIN_DHT, DHT22);

void setup() {
  Serial.begin(115200);
  dht.begin();
}

void loop() {
  delay(2000);                         // el DHT22 mide cada 2 s como máximo
  float h = dht.readHumidity();
  float t = dht.readTemperature();
  if (isnan(h) || isnan(t)) {
    Serial.println("Error leyendo el DHT22");
    return;
  }
  Serial.printf("Temperatura: %.1f C   Humedad: %.1f %%\n", t, h);
}

Reto: enciende un LED cuando la temperatura supere un umbral que definas, y envía la lectura por WiFi o BLE (pestaña anterior).

Práctica 4: servomotor controlado con potenciómetro

Materiales: servo SG90 o similar, potenciómetro de 10 kΩ. Librería: “ESP32Servo”. Un servo pequeño puede funcionar con el 5 V del USB, pero si tiembla o la placa se reinicia usa una fuente externa de 5 V y une su GND con el de la placa.

#include <ESP32Servo.h>

const int PIN_SERVO = 18;
const int POT = 34;
Servo servo;

void setup() {
  Serial.begin(115200);
  servo.setPeriodHertz(50);              // los servos usan 50 Hz
  servo.attach(PIN_SERVO, 500, 2400);    // ancho de pulso mínimo y máximo (us)
}

void loop() {
  int angulo = map(analogRead(POT), 0, 4095, 0, 180);
  servo.write(angulo);
  Serial.println(angulo);
  delay(20);
}

Reto: haz que el servo barra de 0° a 180° y de regreso de forma automática, con la velocidad fijada por el potenciómetro.

Programar con Arduino IDE

Los pasos 1 a 3 se hacen una sola vez. Los pasos 4 a 7 los repetirás en cada proyecto. Se asume Arduino IDE 2.x.

1

Instalar el IDE y el driver USB

Descarga Arduino IDE 2 desde arduino.cc. Si al conectar la placa no aparece ningún puerto, instala el driver del conversor USB-serie que traiga (CP210x o CH340) y prueba con un cable USB que transmita datos (hay cables solo de carga).
2

Agregar el soporte para ESP32

Abre Archivo → Preferencias y en “Gestor de URLs Adicionales de Tarjetas” pega:

https://espressif.github.io/arduino-esp32/package_esp32_index.json

Luego abre el Gestor de tarjetas (icono lateral o Herramientas → Placa → Gestor de tarjetas), busca esp32 e instala “esp32 by Espressif Systems”. Tarda unos minutos.

3

Seleccionar placa y puerto

  • Placa: Herramientas → Placa → esp32 → ESP32 Dev Module (sirve para la mayoría). También puedes usar el selector del menú superior.
  • Puerto: Herramientas → Puerto. En Windows aparece como COM3, COM4…; en Mac como /dev/cu.usbserial-…; en Linux como /dev/ttyUSB0 (puede requerir agregar tu usuario al grupo dialout).
  • Truco: desconecta y vuelve a conectar la placa; el puerto que aparece o desaparece es el tuyo.
4

Administrar librerías

Una librería es código ya hecho para usar un sensor, pantalla o servicio. Herramientas → Administrar bibliotecas (o Ctrl+Shift+I): busca por nombre (por ejemplo DHT sensor library o Adafruit SSD1306) y pulsa Instalar. Acepta instalar las dependencias que te proponga.

Para usarla, agrega al inicio del programa #include <NombreLibreria.h>. Si tienes un archivo .zip: Programa → Incluir biblioteca → Añadir biblioteca .ZIP. Librerías como WiFi.h, Wire.h o SPI.h ya vienen con el soporte ESP32. Los ejemplos están en Archivo → Ejemplos.

5

Las partes de un programa (sketch)

Haz clic en cada bloque para ver qué hace, y pulsa Ejecutar para simularlo.

#include <Arduino.h>
#define LED 2
int cuenta = 0;
void setup() {
  Serial.begin(115200);
  pinMode(LED, OUTPUT);
}
void loop() {
  digitalWrite(LED, HIGH);
  Serial.println("LED ON");
  delay(500);
  digitalWrite(LED, LOW);
  Serial.println("LED OFF");
  delay(500);
  cuenta++;
}
Selecciona un bloque de código.

6

Compilar y cargar a la placa

Verificar (✓) compila y revisa errores sin tocar la placa. Subir (→) compila y envía el programa por USB. Abajo verás el progreso y “Hard resetting via RTS pin…” cuando termine.

Si aparece Connecting......_____ y falla, mantén pulsado BOOT mientras sube y suéltalo al ver el porcentaje. Revisa antes de subir:

MensajeCausa probable
Failed to connect to ESP32Mantén BOOT al subir; revisa el cable; prueba otro puerto USB
No aparece el puertoFalta el driver o el cable es solo de carga
'xxx' was not declaredFalta una librería, #include, o hay un error de escritura
Brownout detector was triggeredAlimentación insuficiente: usa otro cable o fuente
7

El Monitor Serie

Es tu ventana para “ver” lo que piensa el ESP32 y enviarle texto. Ábrelo con el icono de la lupa (arriba a la derecha) o Ctrl+Shift+M.

  • En el código escribe Serial.begin(115200); y en el monitor elige 115200 baud. Si no coinciden, verás símbolos raros.
  • Serial.print() muestra un valor; Serial.println() lo muestra y salta de línea.
  • Para recibir texto: if (Serial.available()) { String s = Serial.readStringUntil('\n'); }
  • Pulsa EN para reiniciar y ver los mensajes de arranque (a 115200).
  • El Serial Plotter (Herramientas) dibuja gráficas de números impresos con println: muy útil para sensores.

Úsalo para depurar: imprime variables en puntos clave y comprueba qué parte del programa se ejecuta. Prueba el cuadro “Enviar al ESP32” del paso 5.
